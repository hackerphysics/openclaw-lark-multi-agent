# LMA 1.8.20

## Live cards identify the actual input

All live input-delivery hints now use a brief localized `【emoji status】` followed by the corresponding original message body or an explicitly bounded excerpt. Local receipt, queueing, submission pending, append queueing, acceptance, processing, waiting/paused, unconfirmed/partial, delivery pending, round ended, no-content, linked reply, interrupted and not-submitted states retain their distinct meaning.

- Concurrent, merged and appended inputs retain independent source references and phases across card updates and recovery. One root's result does not certify another appended input's commitment.
- Necessary unknown/receipt qualifications remain separate from the message preview. Display records do not grant admission, Get/DONE, retry or business-completion authority.
- Literal human text is preserved instead of being mistaken for legacy media/routing markers. Structured media uses visible captions/names/type markers, not server paths, private keys or hydrated document bodies.
- Source identity and recall are checked at the card boundary. Existing known UI cards redact recalled previews without waiting for unrelated reaction network operations; unknown UI effects remain fenced and protected business-answer payloads are not overwritten.
- Complete outer request budgeting preserves newest inputs and marks omissions; user markup cannot create active mentions or card actions.

## Private-chat ownership survives bot renaming

Private ownership is pinned to the receiving application's stable identity. Same-app display-name changes preserve intake/startup access and proven previous-name deduplication. App/chat/message ingress tombstones, including owner-rejected inputs, prevent historical commands from executing again after a rename.

Foreign/malformed pins and unmatched unpinned legacy owners remain fail-closed. Only a separately verified, targeted operator migration can establish a lost legacy alias. No broad takeover or historical-message replay is performed.

## Terminal errors retain their real cause and one delivery owner

Closed run/session abort metadata now survives the foreground collector. Proven total-deadline termination is no longer presented as merely paused waiting; bare `aborted` remains unknown instead of being guessed as a human stop or timeout.

Foreground and late proactive failures coordinate through the existing exact-run error journal/outbox, including compatible legacy owners. Original app/session/physical target/stop epoch/recall checks apply immediately before ordinary admitted-error SDK sends too. New same-run progress during an awaited cause lookup fences stale provisional abort decisions. Finals and explicit stop receipts retain priority.

## Compatibility and operational boundaries

- Runtime dependency constraints and the consolidated plugin contract are unchanged. Preserve compatible target-native dependencies; build and test locally rather than installing/building on deployment hosts.
- Existing history, business namespaces, sync labels and old delivered/unknown-attempt custody are not bulk renamed or replayed.
- This LMA package does not itself upgrade or patch OpenClaw Core, change model selection, increase configured execution deadlines, or alter model permissions.
- Automated acceptance uses offline actual receiver/controller/outbox/Card2 SDK boundaries and synthetic HTTP transport. Real target process activation, original-message delivery and Feishu client appearance require separate deployment/acceptance receipts.
