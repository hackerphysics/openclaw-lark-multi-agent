# 1.8.11 — retained pending inputs and output attribution

These changes are validated offline. Publication, runtime activation, real-model
execution and Feishu delivery are separate verification checkpoints.

## Correctness changes

- Public `pendingInputs.total` counts retained records, not runnable work.
  Complete, identity-matched `interrupted`/`cancelled` records no longer keep a
  session perpetually busy. Queued inputs, real active runs and in-flight work
  still block ordinary admission. Nothing clears or replays Gateway pending
  records, SQLite business rows or stopped work.
- Dispatch inspection follows `nextBefore` as `pendingBefore`, with a 20-row
  request limit, a finite page cap and one 1500 ms overall budget. Missing or
  hidden records, malformed states/identities, duplicate IDs/cursors and changed
  page identity/total remain unknown. Multi-page idle proof rechecks the head;
  this is conservative observation, not a transactional Gateway snapshot.
- Every ordinary handoff uses positive matching dispatch-idle evidence, rather
  than allowing describe-only idle to bypass unknown dispatch state. Existing
  owner/batch/session/stop/admission-window fencing remains in force.
  Proven never-attempted local inputs recover through ordinary paced/startup
  admission; accepted, attempted/unknown and stopped inputs are not replayed.
- Public transcript forwarding can display an input with `role:assistant`.
  Structured input provenance, sender-session markers and public `:user` input
  identities are now excluded before collector, proactive business delivery
  and assistant progress sinks. Missing runId does not turn an input mirror
  into an assistant reply. Internal send/yield tool bodies are also redacted
  before progress/transcript buffering, including identified wrapper results.
- Filtering is based on structured input identity, not body-prefix stripping,
  quote matching, external run IDs, or the provenance of the *run's input*.
  Genuine assistant partial/final output, literal quotations of the reported
  wrapper, ordinary external/Cron results and real continuation replies retain
  their existing output paths. Input receipts and SDK acceptance callbacks
  retain their separate acknowledgment semantics.

## Verification boundaries

Offline tests exercise the actual WS receiver, Client/Bot collectors, progress
cards, durable MessageStore/outbox and public SDK fixtures. Synthetic transports
are explicitly distinguished from an incident raw-frame capture and from live
platform acceptance. Public producer modules were inspected only as source;
no private hashed helper was imported or executed and no OpenClaw host file was
changed. The coordinated `lma-core` plugin remains **0.2.0**.

Deployment, activation and live acceptance remain separate owner-controlled
steps. This candidate does not repair individual historical business rows or
retry already-delivered/internal input mirrors.

## Follow-up

The published 1.8.11 tag does not include the stricter per-page/head inactivity
and absolute head-deadline checks. Use 1.8.12 for that follow-up correction.
