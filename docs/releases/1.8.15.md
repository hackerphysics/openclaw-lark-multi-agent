# 1.8.15 — separate input admission, background outcomes and presentation

## Repair scope

- Ordinary `chat.send` explicitly selects `queueMode: followup` rather than inheriting a session's stored interrupt/steer policy. SDK insertion keeps its existing durable input identity, stop/generation checks and acceptance semantics.
- Collectors use non-destructive exact-run event cursors. Replaced observers cannot steal another run's progress or final; synchronous ACK custody protects same-batch finals. Progress-buffer byte budgets preserve authoritative full results until durable handoff.
- Lifecycle, empty final and message-tool hints trigger exact-run reconciliation, not draft promotion or tool-input replay. Known inter-session input projections and private coordination tool bodies are excluded before output/progress buffering. Genuine assistant quotations and original background results are retained.
- Root completion does not manufacture insertion commitment/DONE for a merely accepted SDK input. Get is acceptance, not proof of model consumption.
- Durable queued/waiting presentation begins before slow admission checks. Card pumps coalesce updates, retain known SDK receipts across local checkpoint failures and do not let unknown old effects silently complete new inputs.
- One silence-watchdog callback has a validated local time bound. A stalled local observer hands its exact outcome to durable/proactive recovery before retiring; it neither stops a business run nor replays input. Cleanup is generation-fenced and cannot clear a successor's guard. Owner release does not wait on card/reaction cleanup. This is not a task-lifetime cutoff.
- Preserve the existing A4 positive-blocker checks (archive, generation conflict and confirmed busy). Unknown admission never authorizes replay of an attempted or stopped input.

- Bridge runtime update only. The coordinated lma-core protocol remains **2**, package **0.2.0**; no Gateway model/config reset or session-history deletion is required.
- Preserve existing bridge state with a coherent SQLite backup before the new presentation tables are initialized. Retain only the verified prior runtime needed for rollback; do not replace platform-compatible native dependencies.
- Windows is independently activated and verified under the actual NSSM data/log paths, not an obsolete home-directory DB.
- Existing accepted/unknown/stopped inputs are not manually replayed. Do not infer delivery from a process/version, transcript, Get or green tests: original-group platform receipts and a post-deployment human request remain separate live acceptance evidence.
- Does not claim to fix upstream native steer commit/target atomicity gaps, nor automatically convert an unknown input receipt into consumption proof.
