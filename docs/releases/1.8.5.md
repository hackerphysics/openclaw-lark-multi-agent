# 1.8.5 — reliability candidate (not published)

- Long silent tools/API calls have no LMA 24-hour failure horizon. Ten-minute
  silence changes presentation only; exact-run custody survives disconnect and
  process restart in LMA-owned SQLite. Queries have short independent deadlines.
- Superseded observers transfer exact-run delivery custody synchronously. Failed
  replacement admission leaves a healthy old collector alive. Admission, owner,
  actual batch and persistent stop generations fence late work and UI updates.
- Inbound requests start with Typing. Get requires actual accepted custody, never
  local queueing, send initiation, a boolean eligibility value or `in_flight`.
  DONE belongs to the exact settled task. UI API failure is independently retried
  and cannot block admission or result delivery.
- Body, file/image/document and supplemental outputs share durable platform
  operation receipts and atomic context/checkpoint registration. Unknown platform
  outcomes fence retry/fallback. Exact platform IDs deduplicate echoes; independent
  identical-text tasks remain distinct. Confirmed partial chunks are recoverable.
- Historical context preview/explicit registration (never resend):
  `node scripts/audit-delivery-context.mjs --db <explicit-path> --bot <name>`.
  `--register --outbox <id> --chat <id> --verified-message-id <actual-id>` requires
  independently verified receipts. Upgrade does **not** auto-backfill live history.

## Explicit external limitation / release gate

The public SDK has real asynchronous acceptance callbacks but **does not provide
an atomic original-run mutation assertion + durable insertion status query**.
A sessionId or an observed lifecycle event is not such authority. This candidate
therefore retains strict mid-run intents as **capability_blocked**, reports it,
and does not pretend to inject or silently run them later. A host public seam
with expected session/run, stable submission identity, no-effect rejection,
read-only receipt query and cancellation classification is needed to enable
strict in-run delivery. No private SDK imports, owner spoofing or host DB edits.

The bridge and lma-core 0.2.0 are a coordinated protocol candidate. This file is
release preparation, **not permission to publish, deploy or restart anything**.
