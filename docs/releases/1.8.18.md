# 1.8.18 — Independently witness every reply in a historical mixed card

Extends 1.8.17's presentation-only fix for a live race observed during validation:
1.8.16 had already reused an old insertion's waiting card for a newer ordinary
run. Closing it from only the old run's reply would be incorrect; leaving it
waiting after both separate replies were delivered would also be misleading.

The card now closes only when **each member's own associated run** has a complete
original-Bot/application/chat/epoch platform reply receipt that postdates that
member. The newer ordinary reply cannot substitute for the older insertion's
reply, or vice versa. Elapsed time uses the latest verified delivery. Persist the
exact related outbox IDs; revalidate all proofs and membership before the effect.
If any verified reply already occupies the card, retain its business content
without a compact replacement. Pending/unknown members still prevent closure.

No input commitment/consumption, Get/DONE, model-sync, admission, business retry,
Core/plugin/config or schema changes. Bridge activation only; native dependencies
are unchanged. Existing unknown-effect fencing and UI-only zero-effect retries
remain intact. 1.8.17 tags/packages are not replaced; this is a new immutable patch.

Validation: bridge/plugins build, public SDK contract, **66 files / 1795 offline
tests**, including 32 linked-card controls (4 new historical mixed-card cases).
Live platform-card readback remains a separate deployment gate.
